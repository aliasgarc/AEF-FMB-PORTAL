OFFLINE DATA FLOW:
  User clicks "refresh" → Service Worker intercepts request
  ├─ Try network (5s timeout)
  ├─ Timeout? → Check IndexedDB cache
  ├─ Found? → Show cached data + "offline" badge
  └─ Not found? → Show "No cached data" message

================================================================================
                         CACHE VERSION UPDATES
================================================================================

WHEN TO UPDATE:
  Edit any file in /public/shared.css or /public/admin/dashboard.html?
  → Update CACHE_VERSION in service-worker.js from 'v1' to 'v2'

HOW TO UPDATE:
  In /public/service-worker.js, change line 1:
    const CACHE_VERSION = 'v2';  // was v1

  Users automatically get new version on next visit.
  Old cache deleted by ACTIVATE event.

================================================================================
                           COMMON QUESTIONS
================================================================================

Q: Do users have to install the app?
A: No, optional. Works as normal website too. Install adds home screen icon.

Q: Does offline viewing require authentication?
A: No, login is network-only (security). But previously cached data
   visible without login if already accessed.

Q: What if my internet is very slow?
A: Service Worker has 5s timeout for APIs. If slower, falls back to
   cached data. Shows "offline" badge so user knows data might be stale.

Q: Can I update the app without users doing anything?
A: Yes. Update CACHE_VERSION in service-worker.js. Users automatically
   get new version on next page load (no manual refresh needed).

Q: What about Safari/iOS?
A: Limited support (no install prompt), but Service Workers still work
   offline. iOS requires manual "Add to Home Screen" via Share button.

Q: How do I clear the cache if there's a problem?
A: Users: DevTools → Application → Cache/IndexedDB → Delete
   Developers: Update CACHE_VERSION to invalidate all caches
